# 16:9 固定课程画布构图

## 先选信息关系

根据本页的主要认知动作选择构图，不按 pageType 套固定皮肤：

- 解释一个核心概念：用一个主模型或主例子建立视觉焦点，辅助说明围绕它展开。
- 比较两个对象：沿相同维度并列或对照，突出真正影响判断的差异。
- 解释过程或时间关系：让方向、阶段和因果在视觉上可追踪，细节按需揭示。
- 完成练习或决策：题干、必要依据、操作和结果反馈组成一个连续任务区。
- 总结与迁移：压缩已经建立的关系，把主要空间留给回忆、应用或行动选择。

同一页只保留一个第一视觉焦点。次要内容通过字号、留白、分组、颜色或渐进揭示降级，不要把所有区域做成同样醒目的卡片。

## 适配学习器舞台

页面以唯一 `main` 作为 1920×1080 设计舞台，宿主负责同比例缩放，并在 1280×720、960×540 和 640×360 三个同比例视口验证。不要复制多页 deck wrapper、导航控制器或作者脚本：

- 16:9 舞台的空间关系在不同屏幕保持一致，使用百分比、网格和同比例字号，不为手机重新排成长页面。
- 先减少重复说明和无效装饰，再重组为主次分栏、对照、中心任务加侧边依据或叠层；不要通过极小正文强行塞入。
- 标题、核心问题、必要解释、学习动作和反馈入口必须在一张舞台内完整可达。
- 图像使用受控视觉区域，保留文字安全区；素材不能决定整页高度。
- 根页面、正文、卡片和互动区都不得滚动。禁止以 `overflow:auto/scroll` 容纳超量内容。
- 同页有多组解释和真实互动时，可用原生 details/summary 或可信互动做渐进揭示，但默认状态仍要给出清楚任务和足够依据。
- reveal、explore 或 sort 是主要学习动作时，让互动项承担比较、区分、排序或探索的核心表达；静态内容只保留操作前不可缺少的少量锚点，不要先用卡片完整讲一遍，再在互动项中重复一遍。
- 页面同时包含支持性 blocks 与 sort 时，组织成“依据列 + 排序任务列”；不要重复讲解同一内容。
- choice 是主要动作时，把题干、选项、提交和反馈作为连续任务区。支持性 recap 只保留作答前不可缺少的判断依据。

## 密度决策

- `sparse`：一个强视觉或一个简单动作，说明很少。
- `balanced`：解释、例子和一次学习动作共同出现。
- `dense`：确有多个必须同时比较的关系；使用紧凑分组或渐进揭示，而不是缩小全部内容。

若内容无法完整装入舞台，先回到本页唯一职责，移除跨页重复和非必要装饰，再改变构图；仍然超载就要求 Course Lead 拆成更多页。不要删掉完成学习目标所需的事实或反馈，也不要用滚动条掩盖问题。
