# 课程架构设计

## 核心目标

先把方向设计正确，再开始生成页面。课程架构必须让每张页面工作单拥有清楚的教学职责和足够上下文，使页面 Agent 能一次产出可信结果，而不是依赖末端反复 QA 和 Repair。

保留 Agent 对内容组织、案例选择和表达方式的判断空间，只固定用户约束、学习结果、页面边界和真实依赖。

## 设计步骤

1. 提取不可丢失的 Brief 事实：受众、先验知识、语言、页数、题目数等数量、学习方式、明确目标和资料约束。
2. 把宽泛目标改写成学习者完成课程后能展示的结果，并为每个结果定义可观察证据。
3. 设计一条有认知推进的课程弧线，而不是把同一主题拆成若干同义页面。
4. 为每页定义唯一职责、关键教学点、学习动作和完成证据；内容形式与互动方式交给页面 Agent 在边界内决定。
5. 只在后页必须读取前页实际生成结果时声明 build 依赖；展示顺序本身不是生成依赖。
6. 在提交前整体阅读一次目标—页面—证据矩阵，修正缺口、重复和难度跳跃，然后提交完整架构。

## 按需读取

- 目标模糊、目标与证据难以对应时，读取 `references/objective-evidence.md`。
- 拆分页职责、安排教学推进或判断生成依赖时，读取 `references/course-structure.md`。

## 质量判断

- 每个目标至少有充分讲解，也有学习者产生证据的机会。
- 不擅自放大用户明确数量；固定画布中的 choice 只规划一道完整题。
- 相邻页面的职责和学习动作明显不同，但术语、事实和难度连续。
- 用户已明确逐页职责时保留原有分工，不让前一页提前消耗后续指定的测验形式；相邻页不以相同互动重复检验同一证据。
- 互动服务于回忆、比较、判断、应用或探索，不作为装饰性要求。
- 素材需求服务于解释和理解，不为了视觉丰富而硬加。
- PageTask 给出方向和验收结果，不预写整页文案或限制唯一实现方式。
- 资料引用只绑定真正依赖的事实；没有命中资料时不伪造来源。
- 首轮架构应足以直接派工；验证工具用于发现遗漏，不用于代替设计。

## 避免

- 不把所有页面串成固定依赖链。
- 不让每页同时承担引入、讲解、练习、总结等全部职责。
- 不用更多页面掩盖目标不清或内容重复。
- 不把 Schema 合法、模板存在或 Gate 通过当作教学质量已经成立。
- 不为方便 Repair 而故意生成保守、空泛或模板化的首稿。
