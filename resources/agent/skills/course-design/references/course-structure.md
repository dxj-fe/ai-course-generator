# 课程结构与页面职责

## 课程弧线

根据主题选择合适弧线，不强制统一模板：

- 概念型：问题或现象 → 核心模型 → 对比例子 → 应用 → 回扣。
- 技能型：真实任务 → 方法拆解 → 示范 → 有反馈练习 → 独立完成。
- 决策型：情境 → 判断标准 → 案例比较 → 权衡练习 → 行动方案。
- 探索型：提出猜想 → 观察证据 → 调整解释 → 新情境迁移。

弧线表达认知推进，不等于固定页面类型序列。

## 页面工作单

每页至少回答四个问题：

1. 本页只负责推动什么理解或能力？
2. 学习者在本页要做什么，而不只是看什么？
3. 页面 Agent 必须保留哪些事实、术语和课程规则？
4. 怎样判断本页已经完成职责？

`purpose` 描述页面在整课中的唯一作用；`teachingPoints` 是必须讲清的事实或关系；`learnerAction` 是学习者行为；`acceptance` 描述结果，不规定唯一布局或文案。

模板选择同时服从信息关系和槽位容量。`story_intro` 只建立情境、问题或任务；两个及以上同层级知识点应使用 knowledge card、comparison 或 timeline 等合适模板。reveal、explore、sort 的每个预期操作项、choice 的每道题都会占用一个 interaction slot，不能选择容量不足的模板后把压力留给 Page Writer 重试。

## 生成依赖

只有出现以下情况才添加 `buildDependsOnPageIds`：

- 后页必须引用前页实际生成的案例、结论或学习者状态；
- 后页任务无法仅凭课程架构独立完成；
- 前页的已验收摘要能显著改变后页内容。

以下情况不构成生成依赖：

- 页面在展示顺序上靠后；
- 希望视觉风格一致；
- 两页属于同一目标；
- 后页只需知道课程架构中已经明确的事实。

尽量让无真实依赖的页面并行生成，同时通过 CourseBlueprint 和 PageTask 保持全局一致。
