## 关键设计决定

### 为什么模板放在 shared

服务端 Skill 需要搜索模板，前端 Gallery 需要展示模板，后续 Planner 和内容 Agent 也会引用模板。模板协议和定义因此属于前后端共享数据，不应分别维护副本。

### 为什么模板不包含 UI 细节

功能模板的稳定语义是教学目标、槽位和约束。颜色、字体、布局和组件实现变化频率更高，属于 Theme、样式模板或渲染层。如果混在一起，任何 UI 调整都会变成 Agent 协议变更。

### 为什么 Skill 返回候选

确定性关键词搜索只能筛选可能的模板，不能理解完整课程节奏、前后页面关系和教学策略。返回多个候选及理由，可以让 Agent 结合 CourseOutline 和相邻 PagePlan 再决定，同时保留可观察的选择依据。

### task card 与 achievement 的处理

Day 08 手册写“任务卡”，Day 07 Schema 使用 `achievement`。本次用 `achievement-task` 模板表达任务与成果确认，并保持 `pageType: achievement`，避免扩大稳定枚举。

## 面试题与详细答案

### 1. 功能模板和组件模板有什么区别？

功能模板描述页面的教学职责和内容结构，例如知识卡需要多个同层级知识块，选择题需要题目、作答和反馈。它面向 Planner、内容 Agent 和质量评估，通常跨技术栈稳定。

组件模板描述页面如何实现，例如 React 组件、属性、DOM、状态管理和响应式布局。它面向前端渲染层，容易随设计系统和框架变化。

两者是一对多关系：一个 `quiz` 功能模板可以由单选题卡片、图片选择、拖拽匹配或移动端逐题组件实现。将两者分开可以保持教学协议稳定，同时允许 UI 持续演进。

### 2. 为什么一句话生成课程时必须先做模板选择？

一句话需求提供的信息有限。如果直接生成内容或 HTML，模型需要同时猜测教学目标、页面职责、知识密度、互动形式和视觉结构，输出空间过大，页面也容易互相孤立。

模板选择先把每页归入明确教学任务，再让内容 Agent 填充规定槽位。它带来四个直接收益：

1. 缩小生成空间，提高结构稳定性。
2. PagePlan 可以在生成 HTML 前被校验和人工查看。
3. 失败可以定位到模板选择或槽位填充阶段。
4. Planner 可以控制整门课程的页面节奏，避免连续出现同一种页面。

模板不是为了消除模型创造力，而是把创造力放在正确边界内：教学职责保持稳定，具体内容和 UI 表现仍可多样。
