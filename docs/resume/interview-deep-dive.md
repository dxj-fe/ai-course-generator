# 课芽简历亮点 · 面试深挖

本文对应 [`project-bullets.md`](./project-bullets.md) 的七条简历亮点。每一节按正常语速可讲约 2–3 分钟，结构统一为“问题 → 方案 → 项目落点 → 结果 → 取舍”。

## 使用方法

1. 先用“30 秒回答”给出结论。
2. 面试官继续追问时，再展开设计和真实代码落点。
3. 结果只描述可由源码、测试、构建或产品界面验证的工程行为。
4. 主动说明边界，不把本地项目包装成分布式生产 SaaS。

## 1. SSE 与可恢复长任务

### 30 秒回答

课程生成不是一次普通请求，所以我把它做成持久化异步任务。服务端只有在课程 checkpoint 写入 SQLite 后才发布公共事件，前端通过严格 SSE 接收 snapshot、增量事件和终态。网络断开只影响观察连接，不会取消任务；重新连接可以用 `Last-Event-ID` 重放缺失事件，暂停、恢复和取消则使用独立的 HTTP 动作。

### 展开讲解

最初的批量 JSON 方案必须等待整门课程完成，用户看不到真实进度，任一页面失败也只能拿到一个总错误。直接把 LangGraph stream 传到浏览器同样有问题：框架 chunk 包含内部节点和状态，协议会随编排实现变化。

我保留 `CourseGenerationState` 作为服务端事实来源。每次节点完成后先校验并持久化 checkpoint，再把允许公开的阶段摘要发布到 EventBus。SSE 只序列化三类消息，业务事件 sequence 同时作为 SSE id。这样浏览器断线后可以先拿持久快照，再重放 cursor 后的事件，避免 UI 猜测缺失状态。

前端边界也做了分层：API client 负责 HTTP，`useSSETask` 负责 EventSource、Schema 校验、重连与去重，`ChatApp` 负责每个会话的任务、draft、附件和页面状态，展示组件只接收投影数据。

### 可验证结果

- 刷新或 SSE 断开不等于取消任务。
- 完成页面保存在 checkpoint 中，恢复时不需要重跑。
- 公开事件不会包含 Prompt、参考资料原文、HTML diff 或 chain-of-thought。
- API、SSE、客户端 Hook 和 Timeline 均有独立测试。

### 取舍与追问

**为什么不用 WebSocket？** 当前主链是服务端单向推送，控制操作频率低，SSE 的事件 ID、自动重连和 HTTP 基础设施更合适。未来出现多人高频协同编辑时再考虑 WebSocket。

**生产化还缺什么？** 活动 runner、AbortController 和 EventBus 仍在单进程内。多实例部署需要耐久队列、任务租约、跨实例事件和幂等执行权。

## 2. 结构化输出与共享状态合同

### 30 秒回答

我没有让模型返回自由 JSON 再由前端容错，而是用 Zod 为每个 Agent 定义唯一输出合同，并用 `CourseGenerationState` 连接全局规划、页面产物、错误、重试和公开事件。模型输出在 Agent 边界、状态合并、持久化和 UI 输入处重复校验，把格式漂移提前变成可定位的阶段错误。

### 展开讲解

AI 应用里最危险的情况不是请求直接失败，而是返回“看起来像对的”对象：少一个字段、枚举翻译成中文、数组被压缩成单值，直到后续 HTML 或 UI 才报错。那时已经很难判断是哪个 Agent 破坏了合同。

项目把课程链路拆成多个明确 Schema，例如 Intent、CoursePlan、PageContentDSL、QualityReport 和 RepairResult。Agent 只负责生成自己的产物，不得同时返回下一阶段结果。状态 patch 进入课程前还会经过节点允许字段检查和完整状态校验，SQLite 读取时同样重新解析。

共享合同也让前端不需要维护第二套业务模型。API client 把 JSON/SSE 转成同一个任务状态，Controller 只做 UI 投影，不复制 Planner 或 Supervisor 规则。

### 可验证结果

- 错误可以定位到 Agent、node、page、stage 和 `causeCode`。
- 手写 Workflow 与 LangGraph 复用同一领域状态，并有 parity 测试。
- 历史 checkpoint 的兼容字段由 Schema 明确处理，而不是组件临时兼容。

### 取舍与追问

**Schema 能保证内容正确吗？** 不能。它保证结构和有限业务不变量；事实、教学和视觉质量需要确定性检查、模型 QA 和人工验收。

**为什么重复校验？** 外部模型、持久化记录和网络数据都是不同信任边界。重复解析的成本远低于错误状态扩散到整条链路。

## 3. 多 Agent、Page Worker 与 LangGraph

### 30 秒回答

我没有按“Agent 越多越好”设计，而是按输入、输出和失败边界拆分职责。Intent 和 Planner 负责全局课程，Pedagogy、Story、Visual 负责专业设计，每页由独立 Worker 执行 Writer、Assets、HTML、QA 和 Repair。LangGraph Supervisor 只是控制面，只能选择后端计算出的合法动作，不能修改业务规则和预算。

### 展开讲解

一个超级 Prompt 同时做课程规划、逐页写作、视觉设计、HTML 和自我评价，会有四类问题：上下文持续膨胀、多页输出容易截断、错误无法归因、单页失败可能重跑整课。

当前设计把全局规划和页面交付分开。全局 Agent 产生整课一致的 CoursePlan 和专业 brief；Page Worker 只拿当前页需要的最小上下文，并维护自己的 attempt、错误和产物。并发生成时，页面结果通过串行 merge/checkpoint 队列进入整课状态，避免覆盖。

LangGraph 用于表达状态和条件路由，但业务规则不放进 Graph 框架对象里。后端先计算合法节点，Supervisor 返回经过 Schema 校验的决策，节点运行前仍检查前置输入、页面目标、attempt 和终止条件。多数场景只有一个合法动作，因此规则优先，不额外调用模型做显而易见的选择。

### 可验证结果

- 页面失败能够独立重试或恢复。
- 已完成页面不会因为其他页面失败而丢失。
- Graph 与手写兼容 Workflow 共用 Agent、Worker、Schema 和 checkpoint 语义。
- Supervisor 无法编造节点、扩大预算或访问完整 HTML。

### 取舍与追问

**为什么还保留手写 Workflow？** 批量兼容入口仍需要它，而且它提供可直接测试的领域执行原语。运行失败时不会自动双跑两套路径，避免重复模型、生图和持久化副作用。

**多 Agent 最大代价是什么？** 调用、延迟、版本和状态都更多，所以固定校验、缓存、历史查询和 ZIP 组装坚持使用确定性代码。

## 4. 功能模板与样式模板

### 30 秒回答

模板系统不是用来替代模型创作，而是稳定教学职责和视觉语言。我把功能模板与样式模板分开：前者规定页面要完成什么教学任务、有哪些内容和互动槽位，后者提供颜色、排版、间距、表面和素材 Token。Planner 选择组合，Page Writer 填内容，HTML Engineer 在合同内实现视觉。

### 展开讲解

只让模型自由生成页面，容易出现整门课都是相同的信息卡，或者每页颜色、密度和互动方式不一致。反过来，如果把课程完全限制为固定 React 组件，视觉表达和生成能力又会变得很弱。

功能 Registry 提供封面、知识卡、对比、时间线、选择题等八类教学模板；样式 Registry 提供六种视觉方向。Planner 保留完整模板 ID 和页面类型 allowlist，确保模型只能选择真实模板；检索层只发送与当前主题相关的少量详细卡片，避免把整个 Registry 塞进上下文。

Page Writer 生成混合 DSL，既保留标题、正文、练习、素材槽和完成条件等稳定语义，也给 HTML Engineer 留出 CSS、布局和视觉层级空间。

### 可验证结果

- 功能模板和样式模板可以独立组合。
- Planner 不能返回不存在的模板 ID。
- 详细卡片是有界检索结果，Registry 和文档有漂移测试。
- UI 的 `/templates` 目录展示同一事实来源。

### 取舍与追问

**为什么不直接让模型写 React？** 生成代码进入主应用运行时会扩大安全、依赖和版本风险。当前产物是受限 HTML，运行在 sandbox 中。

**模板会不会限制创意？** 模板只稳定教学槽位和 Token；DSL 与 HTML Engineer 仍能按主题改变内容、构图和细节。

## 5. 图片素材、缓存与降级

### 30 秒回答

我把图片定义为页面素材，而不是页面本身。Image Prompt 只生成背景、角色、图标和纹理请求，Skill 负责 Provider、格式校验、内部存储和缓存，HTML Engineer 只绑定当前页批准的 URI。非取消类失败会返回 CSS、SVG 或占位 fallback，因此一张图片失败不会让整页丢失。

### 展开讲解

如果让模型生成带标题、按钮或题目的整张课程图片，文字会失去可选择、可翻译、可朗读和响应式能力，互动也只是视觉假象。所以标题、正文和控件始终是 HTML，图片只提供视觉氛围。

素材请求包含类型、角色、比例和无文字约束。生成结果必须是允许的 raster 类型，并保存到服务端内部 URI。缓存使用 Prompt、风格、比例和模型身份等内容键；同一页重跑时还会复用编译后的请求集合，避免 Prompt 随机变化造成重复调用。

取消与 Provider 失败有不同语义：任务取消通过 AbortSignal 立即停止，不能被吞成 fallback；Provider 错误、无效格式或缓存故障可以降级，让 HTML 主链继续。

### 可验证结果

- 页面文本和互动不会烘焙进图片。
- 缺失文件会被识别为 stale cache，并重新生成或降级。
- 取消后不会继续调用后续图片槽。
- 前端只看到公共命中、失败和 fallback 摘要，不看到缓存键或服务端路径。

### 取舍与追问

**为什么不用外部图片 URL？** 内部 URI 便于做格式、来源和生命周期控制，也避免生成 HTML 任意加载第三方资源。

**生产化还缺什么？** 当前是本地文件存储，需要迁移到对象存储、有时效 URL、清理策略和 CDN。

## 6. QA、Repair 与生成 HTML 安全

### 30 秒回答

我把质量判断和修复分开。HTML 先通过确定性合同和安全检查，QA 再结合三个固定视口的 Playwright 证据和模型判断生成六维报告。需要修复时，服务器先决定是 DSL 还是 HTML 问题，并限定可修改的 block 或位置；Repair 只返回候选，候选必须重新校验和 re-QA，连续无改善时安全停止。

### 展开讲解

结构化输出通过并不代表课程可学。页面可能内容稀疏、互动不可用、移动端 overflow、素材缺失，或者包含危险 HTML。单靠程序规则又无法判断解释是否清楚、教学顺序是否合理。

因此我使用分层质量门槛：HTML Engineer 输出后先检查完整文档结构、危险属性、外部资源、DSL marker、素材绑定和互动协议；Page QA 再把静态启发式、桌面/平板/移动三个视口的几何与互动证据，以及模型对内容、教学、排版、风格、HTML、素材六个维度的判断合并成报告。

QA 没有修改权限。确定性分类器根据 issue 决定修 DSL 还是 HTML，并生成有限 RepairRequest。候选应用后重新经过原合同和 QA；如果连续三次没有改善，状态进入 `QUALITY_STALLED`，另有紧急上限防止实现错误形成无限循环。

### 可验证结果

- Repair 无法顺带重写整页或自行宣布通过。
- 每轮尝试、分数、问题和停止原因保存在页面状态。
- Playwright 不可用时会保留明确证据状态，而不是伪造浏览器结果。
- 模型生成 HTML 不进入主应用 DOM，学习运行时由平台拥有。

### 取舍与追问

**为什么不是纯模型 QA？** 程序更适合检查危险属性、overflow 和互动合同；模型更适合判断解释质量和风格一致性，两者互补。

**能保证课程绝对正确吗？** 不能。该闭环提高工程可验证性，最终学科事实、审美和发布仍需要人工门槛。

## 7. 课程历史、播放器与 ZIP 导出

### 30 秒回答

我把生成结果从聊天临时状态变成了持久课程。任务、课程、会话和有时效预览保存在 SQLite；`/course` 提供历史搜索与运行状态，详情页通过受限 sandbox 播放课程，并用浏览器 `localStorage` 保存当前设备的互动进度和朗读偏好；完成课程可以导出课程 JSON、逐页 HTML 和素材 manifest，且不包含私有 Agent 数据。

### 展开讲解

如果课程只存在 React state 中，刷新后就无法恢复，也不能回到历史课程继续学习。生成 HTML 如果直接插入主应用 DOM，又会获得过多权限。

服务端使用同一份经 Schema 校验的课程状态保存任务和产物。`/course` 查询持久课程与运行摘要，`/course/[courseId]` 重新校验页面 HTML 后交给播放器。iframe 允许平台注入的受限学习脚本，但不开放 same-origin、表单、弹窗、下载或任意导航；消息还要检查来源 frame 和共享 Schema。

导出只允许 completed 课程。服务端流式创建 ZIP，包含 `course.json`、按顺序命名的页面 HTML 和素材 manifest。素材 manifest 只记录交付所需的公开字段，不包含 Prompt、缓存键、服务端文件路径或私有推理。

### 可验证结果

- 课程可以搜索、筛选、恢复和继续学习。
- 学习进度与页面互动独立于 Agent 执行状态。
- 未完成课程不能导出正式 ZIP。
- 缺少页面 HTML 时导出会明确失败，而不是生成不完整交付包。

### 取舍与追问

**为什么 ZIP 不直接包含所有图片二进制？** 当前素材仍通过内部 URI 管理，manifest 保留交付关系。离线完整包需要进一步定义资源复制、URL 重写和版权边界。

**生产化还缺什么？** 用户/租户权限、对象存储、发布审批、内容版本和多实例一致性。

## 统一收尾

如果面试官问“最核心的贡献”，可以用下面一句话结束：

> 我的核心贡献不是增加了多少个 Agent，而是把开放模型能力放进了一条结构化、可恢复、可质检、可安全展示的前端产品链路，并为每个失败建立了可定位、可验证的工程边界。
